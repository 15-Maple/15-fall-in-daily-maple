## 1. 스터디 리스트 P
 
### 1.1 목록 조회
- [UI] 카드 컴포넌트 제작 (이름, 소개 일부, 포인트, background 이미지, 생성일 표시)
- [UI] 목록 그리드 레이아웃 (2열 x 3행 = 6개 기준)
- [상태관리] 목록 데이터, 로딩 상태, 에러 상태 관리
- [API] `GET /studies` 최초 진입 시 최신순 6개 호출
- [예외처리] 목록이 하나도 없을 때 빈 상태 UI
- ❓ 카드 소개글 최대 글자수 및 말줄임 처리 기준
### 1.2 검색
- [UI] 검색창 컴포넌트, 검색 버튼/엔터 키 이벤트
- [API] `GET /studies?keyword=` 연동
- [상태관리] 검색어 state, 검색 결과 state 분리 관리
- [예외처리] 검색 결과 0건일 때 안내 문구
- ❓ 검색 대상: 이름만 vs 이름+소개글
- ❓ 디바운스(입력 중 자동검색) 적용 여부
### 1.3 정렬
- [UI] 정렬 드롭다운/탭 UI (최신순 / 오래된순 / 포인트 높은순 / 포인트 낮은순)
- [API] `GET /studies?sort=` 파라미터 연동
- [상태관리] 선택된 정렬값 state, 검색어/페이지와 함께 쿼리스트링 관리
- [예외처리] 정렬 변경 시 페이지네이션 초기화 (1페이지로 리셋)
### 1.4 페이지네이션 (더보기)
- [UI] "더보기" 버튼, 로딩 스피너
- [API] `GET /studies?page=&limit=` 연동
- [상태관리] 현재 페이지 번호, 다음 페이지 존재 여부(hasMore) state
- [예외처리] 마지막 페이지 도달 시 버튼 비활성화/숨김
- ❓ 한 번에 추가로 불러올 개수 (6개? 9개?)
### 1.5 최근 조회한 스터디
- [상태관리] localStorage 유틸 함수 작성 (`saveRecentStudy`, `getRecentStudies`)
- [기능] 상세 페이지 진입 시 저장 로직 실행 (중복 제거 후 맨 앞에 추가, 최대 3개 유지)
- [UI] 홈 화면 상단 "최근 조회한 스터디" 섹션 (카드 3개)
- [예외처리] 저장된 값이 없을 때 "최근 조회한 스터디가 없는 경우" 와이어프레임대로 빈 상태 표시
- ❓ localStorage에 스터디 정보 전체 저장 vs id만 저장 후 재조회

## 2. 스터디 만들기 P
 
### 2.1 생성 폼
- [UI] 입력 폼: 닉네임 / 스터디 이름 / 소개글 / 배경 선택 / 비밀번호 / 비밀번호 확인
- [UI] 배경 선택 컴포넌트 (❓ 이미지 옵션 개수·목록 디자인 확정 필요)
- [상태관리] 각 입력값 state 및 전체 폼 유효성 상태
- [API] `POST /studies` 연동
- [예외처리] 제출 중 중복 클릭 방지 (버튼 비활성화)
- [예외처리] 생성 완료 후 이동 및 완료 토스트
### 2.2 유효성 검사
- [기능] 필수값 검사 (빈 값 제출 방지)
- [기능] 글자수 제한 검사 (이름/소개글 최대 길이)
- [기능] 비밀번호 / 비밀번호 확인 일치 검사
- [UI] 필드별 에러 메시지 표시 위치·문구 통일
- ❓ 비밀번호 형식 규칙 (자리수, 숫자/영문 포함 여부)
- ❓ 닉네임/스터디 이름 중복 허용 여부

## 3. 스터디 상세 P
 
### 3.1 상세 조회
- [UI] 스터디 이름, 생성자 닉네임, 소개글, 포인트, 응원 이모지 상위 3개 렌더링
- [UI] 습관 기록표 영역 (주 단위)
- [API] `GET /studies/:id` 연동
- [예외처리] 존재하지 않는 id 접근 시 에러 페이지로 분기
### 3.2 비밀번호 검증 (공통 모달)
- [UI] 비밀번호 입력 모달 컴포넌트 (삭제/수정/오늘의 습관/오늘의 집중에서 공용)
- [API] `POST /studies/:id/verify-password` 연동
- [예외처리] 불일치 시 토스트 메시지, 입력창 포커스 유지
- ❓ 검증 통과 후 인증 상태 유지 범위 (페이지 이동마다 재검증 여부)
### 3.3 삭제
- [기능] 비밀번호 검증 통과 후 삭제 API 호출 (`DELETE /studies/:id`)
- [예외처리] 삭제 완료 후 리스트로 리다이렉트 + 완료 토스트
- [예외처리] 삭제 확인 재확인 단계 필요 여부 (실수 방지)
### 3.4 수정
- [UI] 생성 폼 재사용, 기존 값 프리필
- [API] `PATCH /studies/:id` 연동
- [예외처리] 수정 완료 토스트, 상세 페이지로 복귀
### 3.5 응원 이모지
- [UI] 이모지 선택 UI (❓ 고정 세트 vs 자유 선택)
- [API] `POST /studies/:id/emojis` 연동
- [기능] 상위 3개 + 개수 집계 로직 (백엔드 집계 권장)
- [예외처리] 이모지 종류 늘어날 때 레이아웃 줄바꿈 처리

## 4. 오늘의 습관 P
 
### 4.1 습관 CRUD
- [UI] 습관 생성 폼 (이름 입력)
- [API] `POST /studies/:id/habits`
- [API] `PATCH /habits/:id` (이름 수정 → 연관 기록 전체 이름 반영)
- [API] `DELETE /habits/:id` → soft delete(`is_active=false`), 과거 기록 유지
- [기능] 신규 습관은 오늘 날짜부터만 기록표에 반영되도록 처리
- ❓ 습관 최대 개수 제한
### 4.2 체크
- [UI] 습관별 체크박스/토글 UI
- [API] `POST /habits/:id/check`, `DELETE /habits/:id/check`
- [기능] 자정 기준 체크 상태 초기화 로직
- ❓ 자정 기준을 서버 시간 vs 클라이언트 로컬 시간 중 어느 걸로 할지
### 4.3 기록표
- [UI] 주 단위 기록표 그리드 렌더링
- [API] `GET /studies/:id/habits/records?week=`
- [기능] 특정 날짜 기준 "그날 활성 상태였던 습관"만 필터링
- [예외처리] 습관이 없을 때 기록표 빈 상태 UI

- [기능] 획득 포인트 studies에 반영 (❓ 실시간 SUM vs 캐시 컬럼)
