# 오늘의 습관 API 구조도 (5개)

프론트 → 백엔드 → DB 관계를 API 1개당 다이어그램 1개로 정리했습니다.

---

## 1. 오늘의 습관 목록 조회

`GET /api/logs/{logId}/habits`

```mermaid
flowchart LR
  FE["프론트\n오늘의 습관 화면"] -->|"GET /api/logs/{logId}/habits\n?cursor&size"| BE["백엔드\n습관 목록 조회"]
  BE -->|"SELECT WHERE log_id=logId\nORDER BY deleted_at, created_at"| DB1[("habits")]
  BE -->|"SELECT 오늘 record_date"| DB2[("habit_histories")]
```

---

## 2. 습관 생성

`POST /api/logs/{logId}/habits`

```mermaid
flowchart LR
  FE["프론트\n습관 목록수정 모달\n('+' 버튼)"] -->|"POST /api/logs/{logId}/habits\n{name}"| BE["백엔드\n습관 생성"]
  BE -->|"INSERT (deleted_at=NULL)"| DB1[("habits")]
```

---

## 3. 습관 이름 수정

`PATCH /api/habits/{habitId}`

```mermaid
flowchart LR
  FE["프론트\n습관 목록수정 모달\n(이름 수정)"] -->|"PATCH /api/habits/{habitId}\n{name}"| BE["백엔드\n습관 이름 수정"]
  BE -->|"UPDATE name"| DB1[("habits")]
  DB2[("habit_histories")] -.habit_id로 join\n과거 기록에도 소급 반영.-> DB1
```

---

## 4. 습관 삭제(비활성화)

`PATCH /api/habits/{habitId}/deactivate`

```mermaid
flowchart LR
  FE["프론트\n습관 목록수정 모달\n(휴지통 클릭)"] -->|"PATCH /api/habits/{habitId}/deactivate"| BE["백엔드\n습관 비활성화"]
  BE -->|"UPDATE deleted_at=now\n(soft delete)"| DB1[("habits")]
  DB2[("habit_histories")] -.영향 없음\n과거 기록 그대로 보존.-> DB1
```

---

## 5. 습관 체크/체크 해제

`PUT /api/habits/{habitId}/check`

```mermaid
flowchart LR
  FE["프론트\n오늘의 습관 화면\n(항목 클릭)"] -->|"PUT /api/habits/{habitId}/check\n{isChecked}"| BE["백엔드\n습관 체크"]
  BE -->|"record_date = 서버 오늘\nUPSERT (habit_id, record_date)"| DB1[("habit_histories")]
```
